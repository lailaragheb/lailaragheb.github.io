Turning Support Documentation Into Guided Customer Experiences

A digital bank, for its customer support agents

The problem

When a customer ran into an error, the support team couldn't see what the customer had seen. To understand what triggered a problem, they needed to view the app screen by screen and replicate the customer's flow. Static documentation couldn't do that.

The solution

I built an interactive, tutorial-based knowledge base from scratch in Arcade. Each tutorial walks an agent through the app screen by screen, so they can follow the same path a customer took.

The scenarios didn't start from a blank page. They came from an FAQ list the bank already had. Together with the product owners, I went through it and picked which FAQs needed a tutorial, and which edge cases were complicated enough to deserve one. Then I turned each one into its own tutorial.

How it's organized

I structured the knowledge base as an Arcade folder organized by product journey, the same way the app is organized. Journey 1 is onboarding, journey 2 is the saving account, and so on. Because it follows the app, an agent can start from where the customer got stuck.

Inside each journey, happy scenarios and negative scenarios sit in separate groups.

Writing

  • One tutorial per scenario. Together with the product owners, I decided which scenarios to include, and each one became its own tutorial.
  • Titles match the scenario. A tutorial's title says which scenario it covers, so an agent can match it to what a customer describes.
  • Both languages. The knowledge base covers English and Arabic, 350+ tutorials in total.

A sample tutorial

The real tutorials show the bank's app, so I can't show them here. This is an invented example, built the same way: a made-up send-money flow, captured screen by screen, with a short instruction on each step. It follows a happy scenario from the home screen to a confirmed transfer.

Training

I presented the knowledge base to the customer support team and taught them how to use it.

Maintenance

The app's UI and content have been revamped several times since I created the tutorials. I'm now sweeping through the included tutorials to bring them in line with the latest screens and copy, and I'm handing the knowledge base over to a junior UX writer and content moderator, who will keep it up to date.

The main lesson: a tutorial built on screenshots goes out of date every time the UI changes. A knowledge base like this needs an owner, a regular review, and a clear way to flag a tutorial as outdated.

Next steps

The next step is to sort the tutorials into two categories: internal and user-facing. Internal tutorials stay with the support team. From the rest, we'll pick the ones that would be useful for customers to see, and add a tutorials section to the bank's website.
