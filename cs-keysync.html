KeySync: Closing the Gap Between Figma and Localization Workflows

Context
A workflow tool for moving copy between Figma and Lokalise
Role
Content Designer. I defined the problem and the workflow, and built the plugin with AI assistance.
Scope
Import, export, and extract workflows for English and Arabic content
Team
Solo project
Tools
Figma plugin, Lokalise, AI-assisted coding
Status
Live and free on Figma Community
ProblemMoving final copy between Figma and Lokalise took about an hour for every 30 keys, or 10 to 16 hours for a full journey.
What I didI defined the workflow and built KeySync, a Figma plugin, with AI assistance. It imports, exports, and extracts keys so nobody copies them by hand.
ResultLive and free on Figma Community, saving up to 16 hours per journey by my estimate.

The problem

Once the copy was final, the real manual work began. For every batch of content I had to:

  1. Create content keys in Figma and export them to Lokalise, key by key.
  2. Copy the keys, with their English and Arabic content, into a Figma variable library by hand.
  3. Publish the variables.
  4. Go back to the design file and connect each variable to its string component, so developers could access the keys.

It took about an hour for every 30 keys. A full user journey has 300 to 500 keys, which came to roughly 10 to 16 hours of repetitive work.

The idea

Instead of copying faster, I wanted to remove the copying. Lokalise's export becomes the single source, and a plugin builds the Figma variables from it.

How it works

KeySync is a Figma plugin with three tabs: Extract, Import and Export. Lokalise stays the source of truth, and the plugin moves keys between it and the Figma variable library, so nobody copies them by hand. It works with English and Arabic.

Extract

Extract creates the keys. Select one or more screens, frames, groups or instances, and KeySync reads every text node inside them and detects each one's component type, such as Title, Label, Description or Hint. Hidden and locked text nodes are included. Empty text nodes are skipped. Text inside images or outlined shapes cannot be extracted. It names each key automatically as JourneyName_TextInCamelCase_ComponentType, so naming is consistent without anyone typing it.

  1. Select your screen in Figma.
  2. Open KeySync and go to the Extract tab.
  3. Enter the journey name, add tags if you want a reference in the export, and tap Extract.
  4. Select or deselect the text nodes you want in the sheet.
  5. Type the Arabic value for each key, right in the plugin.
  6. Export the .xlsx file.
  7. In Lokalise, open Upload, select the file, match the Arabic column to Arabic (Egypt), tap Apply, then tap Import files to add the keys to your project.

Import: create and update

Import builds the Figma variables from Lokalise's export. You drop in the multilingual .xlsx file, and KeySync creates or updates string variables, maps English and Arabic to their own language modes, and organizes the keys into groups and sub-groups that mirror the content structure. Existing values can be updated in both languages.

  1. In Figma, open the library and create a branch. Name it and tap Create.
  2. Open KeySync from inside the branch and go to the Import tab.
  3. Enter a group name. A sub-group is optional. Variables are created as group/subgroup/key-name inside the file's collection.
  4. Tap Choose .xlsx file and select your Lokalise export. The expected columns are Key (A), English (B) and Arabic (C), with headers in the first row. KeySync tells you how many keys it parsed.
  5. Tap Import keys to add them to the library, or Update values to change the ones that already exist.

Export

Export sends new content back to Lokalise without duplicates. From a Figma branch, KeySync exports only the variables created since a baseline, which is a snapshot of the library taken before you add anything.

  1. In Figma, open the library and create a branch. Name it and tap Create.
  2. Open KeySync from inside the branch and go to the Export tab.
  3. Tap Set baseline before you create any keys. The plugin confirms how many existing variables it captured.
  4. Create your string variables, manually or with Import.
  5. Tap Export .xlsx. Only the variables created after the baseline are in the file.
  6. In Lokalise, open your project and tap Upload, select the file, match the Arabic column to Arabic (Egypt), and tap Apply. Then tap Import files to add the new keys to the project.

The result

The plugin saves up to 16 hours per user journey, by my estimate. The old loop of "find text, name key, write Arabic, repeat 300 times" is now "select screen, write Arabic, review, export." The only part left for me is the part that needs a content designer: writing the Arabic.

What's next

KeySync currently supports Arabic as the second language, and I've invited users of other languages to get in touch so I can add them. I also have more plugins and AI-powered tools planned for the less exciting parts of my content workflow.
