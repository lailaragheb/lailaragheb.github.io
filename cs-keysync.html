KeySync: Closing the Gap Between Figma and Localization Workflows

Context
A workflow tool for moving copy between Figma and Lokalise
Role
Content Designer. I defined the problem and the workflow, and built the plugin with AI assistance.
Scope
Import, export, and extract workflows for English and Arabic content
Team
Solo project
Tools
Figma plugin, Lokalise, AI-assisted coding
Status
Live and free on Figma Community, now on its second version
ProblemMoving final copy between Figma and Lokalise took about an hour for every 30 keys, or 10 to 16 hours for a full journey.
What I didI defined the workflow and built KeySync, a Figma plugin, with AI assistance. It imports, exports, and extracts keys so nobody copies them by hand.
ResultLive and free on Figma Community, now on its second version, saving up to 16 hours per journey by my estimate.

The problem

Once the copy was final, the real manual work began. For every batch of content I had to:

  1. Create content keys in Figma and export them to Lokalise, key by key.
  2. Copy the keys, with their English and Arabic content, into a Figma variable library by hand.
  3. Publish the variables.
  4. Go back to the design file and connect each variable to its string component, so developers could access the keys.

It took about an hour for every 30 keys. A full user journey has 300 to 500 keys, which came to roughly 10 to 16 hours of repetitive work.

The idea

Instead of copying faster, I wanted to remove the copying. Lokalise's export becomes the single source, and a plugin builds the Figma variables from it.

How it works

Version 1: import and export. You export keys from Lokalise as a multilingual .xlsx file and drop it into KeySync. It creates or updates string variables, maps English and Arabic to their own language modes, and organizes keys into groups and sub-groups that mirror the content structure. Existing values can be updated in both languages. From a Figma branch, it exports only the variables created since a baseline, so new content goes back to Lokalise without duplicates.

Version 2: extract. After shipping the first version, I realized I'd missed the first step: creating the keys. I was spending hours pulling every string out of a screen, writing the Arabic, and naming each key. So I added an Extract tab. It reads every text node on a selected screen and detects each one's component type. It asks for a journey name, such as "Login", and names each key automatically as JourneyName_TextInCamelCase_ComponentType. Then I write the Arabic directly in the plugin, choose which text nodes to include, and export an .xlsx that is ready for Lokalise or the Figma variables file.

The result

The plugin saves up to 16 hours per user journey, by my estimate. The old loop of "find text, name key, write Arabic, repeat 300 times" is now "select screen, write Arabic, review, export." The only part left for me is the part that needs a content designer: writing the Arabic.

What's next

KeySync currently supports Arabic as the second language, and I've invited users of other languages to get in touch so I can add them. I also have more plugins and AI-powered tools planned for the less exciting parts of my content workflow.
